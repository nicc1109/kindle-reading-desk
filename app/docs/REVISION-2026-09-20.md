# Revisión de Reading Desk — 20 de septiembre de 2026

Reading Desk tiene una propuesta clara: convertir subrayados de Kindle en material para pensar y escribir, conservando una biblioteca local que el usuario puede abrir con Obsidian. La arquitectura actual permite desarrollar esa propuesta sin introducir una base de datos remota ni una cuenta obligatoria. Antes de venderla, la prioridad es proteger el trabajo escrito por el usuario y hacer confiable la actualización del vault.

Esta revisión cubre el código de aplicación, parser, almacenamiento Markdown, Electron/IPC, interfaz y estados, pruebas, compilación, actualizador, distribución Windows, compatibilidad con Sites y dependencias. Incluye reproducciones en un vault temporal, pruebas automatizadas y una comprobación de la nueva función en navegador y Electron. No incluye una auditoría de penetración, prueba de una actualización instalada de punta a punta ni una exportación real a Google, porque todavía no existe el cliente OAuth.

## Lo que ya funciona como base

- Separación entre renderer React, puente de Electron y repositorio del vault.
- Electron con `contextIsolation`, `sandbox` y Node deshabilitado en el renderer; CSP en la página.
- Importación incremental con identidad/hash y revisión de colisiones. Reimportar no debería duplicar y un archivo más corto no elimina lo anterior; hay pruebas para esos casos.
- Markdown legible, regiones administradas y conservación de contenido externo durante importaciones.
- Biblioteca centrada en libros, pasaje completo separado del extracto, notas, reflexión, autores y paneles ajustables.
- Build reproducible con lockfile, flujo de release de Windows y pruebas del adaptador de Sites.

## Avance de implementación P1

Los cuatro hallazgos P1 quedaron aplicados después de esta revisión:

- Las fusiones ahora parten del Markdown actual del destino, conservan frontmatter desconocido y texto no administrado, y guardan copias recuperables de ambos libros con un manifiesto antes de escribir. La fuente fusionada continúa archivándose en `.kindle-library/merged`.
- El watcher observa los directorios `Books` y `Authors`, filtra Markdown y cubre crear, modificar, renombrar y borrar. La interfaz muestra si está observando el vault o si el watcher informó un error, en lugar de afirmar incondicionalmente que está actualizado.
- Las mutaciones del vault comparten una cola de escritura. Las ediciones de clippings releen el libro desde disco, aplican el parche sobre esa revisión y rechazan la escritura si el archivo cambió antes de guardar. Las pruebas cubren la edición externa reproducida y parches concurrentes.
- Se actualizaron de forma controlada Electron, electron-builder, electron-updater, Vite, Vitest, Playwright y YAML, además de sus dependencias transitivas corregidas. `npm audit` informa 0 vulnerabilidades conocidas; el build, las pruebas y un instalador NSIS con Electron 44 fueron validados. No se usó `npm audit fix --force`.

La detección de conflictos reduce la ventana de sobrescritura accidental, pero no equivale a un bloqueo transaccional entre procesos. La restauración guiada y una acción visible para deshacer fusiones siguen siendo mejoras de producto pendientes.

## Avance de implementación P2

Los seis hallazgos P2 quedaron aplicados después de esta revisión:

- El workspace sincroniza revisiones nuevas del mismo libro sin reemplazar borradores locales sucios. Las notas por clipping y la reflexión del libro mantienen borradores por ID, numeran las revisiones de guardado, encadenan escrituras y esperan el guardado antes de cambiar de clipping. Una edición realizada mientras otra escritura está pendiente continúa marcada como no guardada.
- Importaciones, fusiones, edición de metadatos, selección del vault, apertura de archivos y actualización de la aplicación tienen estados de error recuperables. Los estados ocupados se limpian en `finally`; una resolución de conflicto fallida restaura la elección anterior y una fase de refresco fallida no se presenta como importación exitosa.
- Los QA de navegador y Windows ahora usan aserciones y fallan ante controles falsos o errores de ejecución. Los selectores y la versión esperada se toman de la interfaz y del paquete actuales. Se agregó CI para `push` y `pull_request` con instalación reproducible, auditoría, pruebas, build y comprobación de Sites.
- Todos los handlers IPC validan el sender, el frame principal, la URL exacta del renderer y los argumentos recibidos. La ventana bloquea navegación/redirección no prevista, webviews y solicitudes de permisos. Las pruebas rechazan remitentes, frames, URLs, parches y resoluciones no autorizados.
- Las claves de identidad admiten letras y números Unicode. El parser suma metadatos y fechas en alemán, francés e italiano, y produce advertencias por entrada cuando no puede inferir el autor. El esquema Markdown subió a versión 3 y la lectura de versiones anteriores conserva la clave histórica mientras agrega la equivalente Unicode.
- Las pruebas cubren actualización externa del mismo libro con borrador sucio, selección rápida y escritura durante guardados lentos, reflexión de libro concurrente, remitentes IPC inválidos, fixtures multilingües y migración de claves v2 a v3.

La confirmación de salida del proceso protege solo borradores todavía sucios; no aparece cuando todos los cambios ya fueron persistidos. El esquema conserva las claves anteriores para compatibilidad, por lo que no requiere reescribir de inmediato todos los archivos del vault.

## Avance de implementación P3

Los dos hallazgos P3 quedaron aplicados después de esta revisión:

- `App.tsx` bajó de 1.018 a 802 líneas. La biblioteca, navegación lateral, vistas estáticas, configuración, formateadores, estado del vault/actualizaciones, foco roving y ventanas virtuales ahora viven en módulos separados. El workspace conserva junto el flujo estrechamente acoplado de lectura y borradores.
- `BookSummary` dejó de incluir `searchText` con citas, reflexiones y etiquetas de cada clipping. La búsqueda de biblioteca trabaja solo con título, autores y etiquetas del libro; el snapshot ya no replica toda la prosa del vault al renderer.
- Se midieron 1.000 libros y 50.000 registros. Resumirlos tomó **0,60 ms**, filtrar 1.000 metadatos **2,29 ms** y el payload resultó de **133.057 bytes** en la corrida registrada. Por eso no se añadió un índice de búsqueda adicional.
- La lista sin virtualizar de 1.000 libros tardó **1.446,63 ms** en renderizar y **2.712,22 ms** en la consulta accesible de jsdom, unos **4.158,85 ms** combinados. Se implementó una ventana virtual compartida para libros y clippings. Con ella, la corrida equivalente tomó **142,48 ms** de render y **160,25 ms** de consulta, unos **302,73 ms** combinados, manteniendo `aria-setsize` y `aria-posinset`. Estas cifras son mediciones de regresión locales, no un SLA de producción.
- Tabs y listboxes usan un único punto de tabulación, flechas con wrap, `Home`/`End`, selección que sigue al foco y búsqueda incremental por teclado en listas. El QA de navegador verifica foco y activación reales, además de la presencia del listbox y sus opciones con nombre en el árbol de accesibilidad de Chromium.
- Se añadió una prueba de contraste sobre los tokens activos. Texto normal y foco cumplen los umbrales AA comprobados; verde y ámbar se oscurecieron ligeramente para superar 4,5:1 sobre el fondo papel.

La virtualización mantiene alturas de fila estables y limita el DOM sin recortar los datos disponibles. La búsqueda global dentro del contenido de clippings no se incorporó: si se añade como función futura, debe usar una consulta explícita bajo demanda o un índice local, no volver a inflar el snapshot principal.

## Primera feature implementada: Google Docs

Se agregó una acción por libro con vista previa, cantidad real de subrayados, estado no configurado, autenticación externa, creación del documento y enlace de resultado. Todos los subrayados se exportan completos y en negrita; las referencias y párrafos `Notes:` quedan en texto normal. No se exportan notas Kindle, marcadores ni reflexiones de esta primera versión.

El documento es una copia independiente. Reexportar crea otro documento, por lo que no destruye anotaciones escritas después. El exportador relee el libro desde el vault, no toma solo lo visible ni depende de un filtro. Si falta texto en el archivo Kindle, lo señala: no puede recuperar contenido que Kindle nunca exportó.

El flujo OAuth usa permisos de archivo limitados, PKCE y receptor temporal local; no persiste tokens ni los expone al renderer. Hay cancelación, plazos de espera y resultado parcial con enlace cuando la creación ya ocurrió. El modo navegador no simula una subida exitosa.

Pendiente acordado: crear/configurar el cliente OAuth Desktop y validar con una cuenta real. Guía: [GOOGLE-DOCS.md](GOOGLE-DOCS.md). Antes de entregar al público, la identidad OAuth debe venir provisionada por Reading Desk; configurar Google Cloud no debe ser una tarea del comprador.

## Producto: mejoras recomendadas

1. **Confiabilidad del vault.** Resolver P1, añadir backups/versiones recuperables y una operación de deshacer fusiones. El contenido del usuario es el activo principal.
2. **Primer valor en pocos minutos.** Mejorar onboarding: dónde encontrar `My Clippings.txt`, elegir carpeta, explicar duplicados y mostrar el primer libro exportable. Usar biblioteca de ejemplo claramente identificada.
3. **Del subrayado a la escritura.** Plantillas «resumen de libro», «seminario» y «reseña», selección por etiquetas y exportación de varios libros en un dossier. Mantener citas diferenciadas de comentarios propios.
4. **Encontrar lo leído.** Búsqueda dentro del libro y global con contexto, favoritos/etiquetas filtrables y enlaces a página/posición. Evitar inflar métricas: los clippings no permiten inferir horas leídas ni progreso real.
5. **Portabilidad.** Exportación Markdown/HTML/DOCX, restauración de backups y edición sencilla de metadatos. Google Docs es la primera integración externa, no una razón para bloquear el acceso a los datos locales.
6. **Estudio recurrente, después.** Repaso espaciado y colecciones temáticas. Validar demanda antes de construir sincronización entre dispositivos, colaboración o servicios de IA con costos recurrentes.
